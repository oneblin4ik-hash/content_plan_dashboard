# Crimson Studio

Личная контент-студия Эдуарда Серболина: банк идей, папки и генератор тем для Telegram и Reels.

Это **самостоятельное приложение**, не связанное с Manus. Оно живёт на Cloudflare Workers, хранит данные в собственной базе D1 и генерирует идеи через Gemini по твоему ключу. Старое приложение в `apps/content-studio/` продолжает работать — этот проект его не трогает.

---

## Что нужно один раз настроить

База данных **уже создана** — `crimson-studio` в аккаунте Cloudflare владельца, её идентификатор прописан в `wrangler.jsonc`, таблицы применены. Остаётся выложить приложение и положить три секрета.

Ключи и код-фразу **никому не пересылай**: они вводятся прямо в Cloudflare и в репозиторий не попадают.

### Способ А — через браузер, без терминала

Cloudflare умеет сам собирать проект из GitHub. Это основной путь.

1. **Workers & Pages** → **Create** → вкладка **Workers** → **Import a repository**.
2. Подключи GitHub, выбери `content_plan_dashboard`, ветку `main`.
3. Заполни поля сборки:

   | Поле | Значение |
   |---|---|
   | Project name | `crimson-studio` |
   | Root directory | `apps/studio-v2` |
   | Build command | `pnpm install && pnpm build` |
   | Deploy command | `npx wrangler deploy` |

   `Root directory` можно оставить пустым — в корне репозитория лежит `wrangler.jsonc`, который соберёт и выложит это приложение. Заполненное поле просто ускоряет сборку: не собирается лишний соседний проект.

4. **Create and deploy**.
5. Открой воркер → **Settings** → **Variables and Secrets** → добавь три записи типа **Secret** (не Text):
   `STUDIO_PASSPHRASE`, `AUTH_SECRET`, `GEMINI_API_KEY`.

Секреты подхватываются сразу, пересобирать не нужно. Дальше каждое изменение в `main` выкладывается автоматически.

### Если сборка упала

Cloudflare показывает лог по ссылке из уведомления о сборке.

- **`Missing entry-point to Worker script`, а выше в логе собирается что-то постороннее** — `dist/public/…`, `mermaid`, `cytoscape`. Значит, сборка идёт в корне репозитория, где лежит другой проект. На этот случай в корне есть свой `wrangler.jsonc`, который собирает и выкладывает `apps/studio-v2`, так что пустой `Root directory` больше не мешает. Если ошибка всё-таки появилась — проверь, что корневой `wrangler.jsonc` на месте.
- **Сборка прошла, а адрес отдаёт 404 и `error code: 1042`** — проверь `Deploy command`. `npx wrangler versions upload` только загружает предварительную версию и ничего не публикует; для живого адреса нужен `npx wrangler deploy`.

Корневой `wrangler.jsonc` дублирует настройки этого приложения, и расхождение между двумя файлами развернуло бы не то. Поэтому `pnpm test` сверяет их и падает с понятным сообщением, если они разошлись.

### Способ Б — из терминала

```bash
cd apps/studio-v2
pnpm install
pnpm exec wrangler login
pnpm deploy
```

```bash
pnpm exec wrangler secret put STUDIO_PASSPHRASE
pnpm exec wrangler secret put AUTH_SECRET
pnpm exec wrangler secret put GEMINI_API_KEY
```

Ключ Gemini заводится бесплатно на [aistudio.google.com](https://aistudio.google.com/apikey). `AUTH_SECRET` — длинная случайная строка, например из `openssl rand -base64 32`.

Адрес будет вида `https://crimson-studio.<аккаунт>.workers.dev`. Открывай с телефона: приложение спросит код-фразу и запомнит её на 90 дней.

### Разворачиваешь в другом аккаунте Cloudflare?

Записанный в `wrangler.jsonc` идентификатор принадлежит базе владельца, и чужому аккаунту она недоступна — деплой упадёт. Заведи свою и подставь её идентификатор:

```bash
pnpm exec wrangler d1 create crimson-studio   # напечатает database_id
# впиши его в wrangler.jsonc вместо существующего
pnpm db:remote                                 # создаст таблицы
```

## Команды

| Команда | Что делает |
|---|---|
| `pnpm dev` | Клиент с горячей перезагрузкой (нужен запущенный `dev:worker`). |
| `pnpm dev:worker` | Сервер и локальная база на `localhost:8787`. |
| `pnpm check` | Проверка типов во всех трёх окружениях. |
| `pnpm test` | Тесты против настоящей локальной базы D1. |
| `pnpm test:smoke` | Браузерный сценарий на живом приложении. |
| `pnpm build` | Сборка клиента. |
| `pnpm deploy` | Сборка и выкладка. |
| `pnpm db:generate` | Создать миграцию после правки схемы. |
| `pnpm db:local` / `pnpm db:remote` | Применить миграции локально / в бою. |

Перед отправкой изменений прогоняй минимум:

```bash
pnpm check && pnpm test
```

### Локальный запуск

```bash
cp .dev.vars.example .dev.vars     # впиши свои значения
pnpm db:local
pnpm dev:worker
```

Браузерный сценарий требует запущенного приложения и Chromium. Путь к браузеру задаётся переменной — жёстко он нигде не прописан:

```bash
STUDIO_URL=http://127.0.0.1:8787 \
STUDIO_PASSPHRASE=твоя-фраза \
CHROMIUM_PATH=/usr/bin/chromium \
pnpm test:smoke
```

## Как устроено

| Слой | Ответственность | Файлы |
|---|---|---|
| Сервер | Маршруты API, вход, лимиты. | `worker/index.ts`, `worker/routes/api.ts` |
| Вход | Код-фраза, подписанная кука, защита от подбора. | `worker/auth.ts` |
| Данные | Запросы к D1 через Drizzle. | `worker/store.ts`, `db/schema.ts` |
| Генератор | Промпт, разбор ответа, фильтр выдумок. | `worker/llm/` |
| Клиент | Экраны, движение, тактильный отклик. | `client/src/` |
| Общее | Схемы проверки и данные о сегментах. | `shared/` |

### Данные

Четыре таблицы: `folders`, `ideas`, `drafts`, `usage`.

У каждой идеи есть **папка и дата создания** — на них держатся фильтр и сортировка. Удаление не стирает запись, а проставляет `deleted_at`: тридцать дней идею можно вернуть, потом она удаляется окончательно.

`drafts` хранит результат генерации **до** того, как ты нажал «Сохранить». Свернул приложение, отвлёкся, телефон выгрузил вкладку из памяти — идеи на месте, генерация не потрачена впустую.

Схему меняй только через миграции: правишь `db/schema.ts`, затем `pnpm db:generate`, затем применяешь.

### Генератор

Провайдер выбирается переменной `LLM_PROVIDER` в `wrangler.jsonc`: `gemini` (по умолчанию), `deepseek` или `openai`. Модель — `LLM_MODEL`. Смена провайдера не требует правок кода, только своего ключа в секретах.

Генератор **не выдумывает клиентов, отзывы и кейсы**: ответ модели проверяется, и текст с признаками выдуманной истории отклоняется целиком. Не ослабляй эту проверку — за такие тексты пришлось бы отвечать публично.

Число генераций в сутки ограничено переменной `DAILY_GENERATION_LIMIT` (по умолчанию 20), счётчик живёт в базе. Неудачная генерация квоту не тратит.

### Доступ

Приложение открыто по ссылке, поэтому вход закрыт код-фразой. Она сверяется на сервере за постоянное время, кука подписывается HMAC-SHA256 и живёт 90 дней. Десять неудачных попыток с одного адреса за пять минут — и адрес блокируется. Смена `STUDIO_PASSPHRASE` разлогинивает все устройства.

### Внешний вид

Дизайн-система **Crimson**: красное на чёрном, `Unbounded` в заголовках, `Manrope` в интерфейсе. Все значения — в `client/src/styles/tokens.css`, компоненты берут только их.

Из системы перенесены «стекло 2.0» (диагональная заливка под 152°, `blur(24px) saturate(180%)`, световая кромка сверху и тёмная снизу) и глянцевые кнопки с трёхстоповым градиентом.

Сверху добавлены движение и отклик:

- **3D-наклон** карточек за пальцем с пружинным возвратом — `useTilt`.
- **Параллакс** из четырёх слоёв, всё на `transform` — `useParallaxField`.
- **Свайпы** между разделами — `useSwipeNavigation`.
- **Тактильный отклик** — `lib/haptics.ts`. Вибрация там, где браузер её даёт; Safari её сайту не даёт, поэтому кнопка вжимается через `data-haptic-pressed`. Не заменяй этот запасной вариант обходами платформы.

При включённом в системе «уменьшении движения» анимации выключаются, интерфейс остаётся полностью рабочим.

## Правила изменений

1. Интерфейс рассчитан на **iPhone 16 Pro (402×874)**. Цель нажатия — **не меньше 44 px**; браузерный сценарий это проверяет и падает, если стало меньше.
2. Цвета и шрифты берутся **только из токенов**. Прямые значения в компонентах ломают систему.
3. Анимируй **только `transform` и `opacity`** и уважай `prefers-reduced-motion`.
4. Новый класс не должен пересекаться по имени с существующим — `.label` для полей формы и `.btn-label` внутри кнопки живут отдельно намеренно.
5. Проверка ввода описывается в `shared/types.ts` и применяется на сервере. Клиент не последняя линия обороны.
6. Секреты и `.dev.vars` в Git не попадают.

## Выгрузка данных

Раздел «Данные» выгружает всё рабочее пространство в JSON. Загрузка **добавляет, а не затирает**: повторный импорт того же файла не создаст дублей — совпадения ищутся по теме и дате создания.

Делай выгрузку раз в месяц. Что бы ни случилось с Cloudflare или с этим репозиторием, банк идей останется у тебя.
