# Архитектура личной Content Studio · версия 1

## Продуктовая граница

Новая Content Studio — закрытый рабочий инструмент Эдуарда Серболина. В первой версии он не выполняет ИИ-генерацию, не публикует в социальные сети и не импортирует старые материалы. Его задача — дать единое, быстрое место для сбора тем, работы по шаблонам, планирования Telegram-постов и Reels, хранения материалов и ручного учёта результатов.

Доступ выполняется через существующую авторизацию Manus. Все данные привязываются к владельцу, хранятся в базе данных и поэтому сохраняются при входе с другого устройства. Серверные операции будут доступны только владельцу проекта.

## Навигация

| Раздел | Назначение первой версии | Главное действие |
|---|---|---|
| Идеи | Банк тем с папками, поиском, фильтрами и приоритетом | Создать идею или отправить её в Studio |
| Студия | Собрать черновик по шаблону без ИИ: Telegram-пост или сценарий Reels | Создать материал и сохранить в библиотеку |
| План / календарь | Распределить темы и готовые материалы по датам | Поставить материал в план или обновить статус |
| Библиотека | Хранить, редактировать, копировать и помечать материалы | Открыть, скопировать или назначить дату |
| Голос и ЦА | Редактировать профиль Serbolin и сегменты S1–S4 | Изменить контекст для шаблонов |
| Аналитика | Вносить показатели опубликованных материалов и видеть краткие итоги | Добавить результат публикации |

## Постоянная модель данных

| Сущность | Назначение | Ключевые поля |
|---|---|---|
| `content_folders` | Пользовательские папки для идей и материалов | пользователь, название, цвет, порядок |
| `content_items` | Единый реестр идей, черновиков и готовых материалов | тип, канал, заголовок, хук, текст, сегмент, формат, приоритет, статус, папка, дата публикации |
| `content_templates` | Личные шаблоны структур Telegram-поста и Reels | тип, название, структура, инструкция, активность |
| `voice_profiles` | Профиль голоса автора | тон, обращение, энергия, структура, доказательства, CTA, запреты |
| `audience_segments` | Изменяемые сегменты S1–S4 | позиция, название, задача, боль, страх, триггер, оффер, цвет |
| `content_metrics` | Ручные метрики опубликованных материалов | материал, дата, просмотры, реакции, комментарии, сохранения, пересылки, переходы, заявки |
| `studio_settings` | Выбранный по умолчанию сегмент и вспомогательные предпочтения | пользователь, активный сегмент, целевая цель, дата обновления |

## Дизайн-система

Интерфейс будет работать как плотная профессиональная панель: фиксированный сайдбар, широкая рабочая область, быстрые действия в контексте карточки и минимум переходов. Светлая основа строится на тёплом почти белом фоне, графитовой типографике и акцентах глубокого красного; стеклянные поверхности применяются локально для фокусных панелей и служебных блоков, а не как универсальная замена контрасту. Градиенты используются в крупных, но сдержанных цветовых пятнах и сохраняют читаемость.

## Техническая карта реализации

| Зона | Целевые файлы | Ответственность |
|---|---|---|
| Схема и миграция | `drizzle/schema.ts`, новая SQL-миграция в `drizzle/` | Таблицы папок, материалов, шаблонов, голоса, сегментов, настроек и метрик с привязкой к владельцу. |
| Доступ к данным | `server/db.ts`, `server/db/contentStudio.ts` | Изолированные запросы CRUD к материалам, папкам, шаблонам, профилям, сегментам и метрикам. |
| API и защита | `server/routers.ts`, `server/routers/contentStudio.ts` | tRPC-процедуры, разрешённые только владельцу: загрузка стартовой базы, создание, изменение, удаление, планирование и внесение показателей. |
| Тесты | `server/contentStudio.test.ts` | Проверка правил доступа, валидации, построения плана и преобразования аналитических данных. |
| Каркас интерфейса | `client/src/App.tsx`, `client/src/components/StudioShell.tsx`, `client/src/index.css` | Защищённый рабочий интерфейс, сайдбар, адаптивная навигация, общая визуальная система и состояния загрузки. |
| Разделы | `client/src/pages/IdeasPage.tsx`, `StudioPage.tsx`, `PlannerPage.tsx`, `LibraryPage.tsx`, `VoiceAudiencePage.tsx`, `AnalyticsPage.tsx` | По одной странице на согласованный рабочий раздел, без смешения сценариев в одном большом компоненте. |
| Повторяемые элементы | `client/src/components/content-studio/` | Диалоги создания/редактирования, карточки материалов, фильтры, форма шаблона, календарный слот, метрики и пустые состояния. |
| Типы и посев бренда | `shared/contentStudio.ts`, `shared/contentStudioSeed.ts` | Общие типы и начальные данные Serbolin/S1–S4, создаваемые только для владельца при первом входе. |

В существующем проекте отсутствуют полноценные серверные модули шаблона, несмотря на включённую возможность базы данных и авторизации. Поэтому реализация начнётся с приведения структуры к поддерживаемой модели tRPC + Manus OAuth + Drizzle, а затем будет построен интерфейс поверх постоянных данных.

## Граница первой версии

Функции ИИ-генерации, интеграции с Telegram/Instagram, автосбор аналитики, импорт старой базы и экспортные документы сознательно исключены из первого релиза. Структуры данных и интерфейсные точки расширения будут заложены так, чтобы эти возможности можно было добавить в следующем этапе без перестройки пользовательской базы.
