# OpenMontage для русского вертикального видео

Рабочая обвязка над [OpenMontage](https://github.com/calesthio/OpenMontage) для монтажа
вертикального ролика с русскими субтитрами и анимацией — **только на бесплатных
инструментах**, без единого API-ключа.

## Что здесь лежит

| Файл | Назначение |
|---|---|
| `produce.py` | Конвейер: анализ → распознавание → чистка звука → цветокор → субтитры и оверлеи → QA |
| `openmontage-ru-fixes.patch` | Четыре правки в апстрим OpenMontage, без которых русский не работает |
| `cyrillicFonts.ts` | Модуль загрузки кириллических шрифтов для Remotion |
| `build_cyrillic_fonts.py` | Ставит модуль и `HookTitle.tsx` на место, генерирует из `fonts/` вшитые в бандл base64-данные |
| `HookTitle.tsx` | Титр-крючок: строки появляются по одной, обводка, красный акцент |
| `assemble_takes.example.py` | Пример сборки ролика из отобранных дублей с покадровыми субтитрами |
| `reels/take_split.py` | Режет сырую запись на дубли и распознаёт каждый отдельно |
| `reels/grade_match.py` | Меряет тональный профиль образца и оценивает цепочки цветокора |
| `reels/caption_spec.py` | Снимает параметры субтитров с образца и проверяет по ним готовый ролик |
| `fonts/` | Кириллические сабсеты Montserrat, Inter, Playfair Display, Oswald, Rimma Sans (woff2, ~120 КБ) |

## Что пришлось починить в OpenMontage

Апстрим не готов к кириллице и к самому себе. Найдено и исправлено при прогоне:

1. **Композиции используют Space Grotesk, у которого нет кириллицы вообще.**
   Русский текст падал в fallback. Заменено на Montserrat/Inter/Playfair
   с кириллическими сабсетами, вшитыми в бандл как base64 — рендеру больше
   не нужен `fonts.gstatic.com`.

2. **`remotion_caption_burn` формировал путь `public/talking-head/<file>`,
   а `staticFile()` этот префикс явно запрещает.** Основной путь инструмента
   падал всегда; работал только ffmpeg-фолбэк. Префикс убран.

3. **Разделитель слов в субтитрах пропадал.** Пробел стоял внутри
   `inline-block` со `white-space: nowrap`, где браузер обрезает концевой
   пробел — слова слипались («Иван,исегодня»). Затрагивает любой язык
   с пробелами, не только русский. Разделитель вынесен наружу спана.

4. **Слово субтитра висело на экране всю паузу после реплики.** Страница
   держалась до начала следующей — то есть последнее слово фразы оставалось
   на кадре через всю тишину и переживало любую склейку внутри неё. Добавлен
   `maxHoldMs`: страница не задерживается дольше своего последнего слова
   более чем на заданное время. Без параметра поведение прежнее.

5. **`face_tracker` падал на mediapipe 1.0**, где выпилен legacy-API
   `mp.solutions`. Проверка доступности теперь смотрит на сам API, а не на
   факт импорта; в связке используется mediapipe 0.10.14.

Плюс правка на стороне вызова: `audio_enhance` кодирует в AAC независимо от
расширения, поэтому `.wav` на выходе даёт битый контейнер — просим `.m4a`.

## Установка

```bash
git clone https://github.com/calesthio/OpenMontage.git
cd OpenMontage && make setup

# распознавание речи и трекинг лица
.venv/bin/python -m pip install faster-whisper opencv-python-headless "mediapipe==0.10.14"

# правки под кириллицу: сначала шрифтовые модули, потом патч
python /path/to/openmontage-ru/build_cyrillic_fonts.py --composer remotion-composer
git apply /path/to/openmontage-ru/openmontage-ru-fixes.patch
```

Порядок важен. Патч правит 23 файла композиций так, что они импортируют
`./lib/cyrillicFonts`, а сам этот модуль в патче не лежит — его ставит
`build_cyrillic_fonts.py`. Скрипт кладёт `cyrillicFonts.ts` в
`remotion-composer/src/lib/`, генерирует рядом `cyrillicFontData.ts`
(base64-сабсеты, вшитые в бандл) и копирует woff2 в `public/fonts/`.

Проверить, что всё встало:

```bash
cd remotion-composer && npx tsc --noEmit -p tsconfig.json
```

Нужны также `ffmpeg`, `Node.js 18+` и Chromium для Remotion
(`REMOTION_BROWSER_EXECUTABLE`, если Remotion не может скачать свой).

## Запуск

```bash
REMOTION_BROWSER_EXECUTABLE=/path/to/chromium \
OPENMONTAGE_ROOT=/path/to/OpenMontage \
python produce.py video.mp4 --outdir out --overlays overlays.json
```

Ключи: `--model` (по умолчанию `large-v3`), `--language ru`,
`--words-per-page`, `--font-size`, `--highlight`, `--grade`, `--skip-audio`.

### Формат оверлеев

```json
[
  {"type": "hero_title",  "in_seconds": 0.3, "out_seconds": 3.2,
   "position": "full_overlay", "text": "ЗАГОЛОВОК"},
  {"type": "callout",     "in_seconds": 6.7, "out_seconds": 9.2,
   "position": "upper_third", "text": "Тезис", "callout_type": "tip"},
  {"type": "stat_card",   "in_seconds": 9.4, "out_seconds": 11.3,
   "position": "lower_third", "stat": "100%", "text": "подпись"}

```

Доступные типы: `hero_title`, `section_title`, `text_card`, `stat_card`,
`stat_reveal`, `callout`, `comparison`, `bar_chart`, `line_chart`,
`pie_chart`, `kpi_grid`.

### Стиль субтитров коротких видео

Композиция `TalkingHead` принимает параметры внешнего вида субтитров.
Значения ниже воспроизводят типовой вид Reels: одно слово на экране,
капсом, узким гротеском, без плашки, на 63% высоты кадра.

```json
{
  "wordsPerPage": 1,
  "fontSize": 117,
  "captionFontFamily": "\"OM Condensed\", Oswald, sans-serif",
  "captionColor": "#FFFFFF",
  "captionBackgroundColor": "transparent",
  "captionVerticalPosition": 0.679,
  "captionTextTransform": "uppercase",
  "captionScaleX": 0.788,
  "captionTextShadow": "6px 6px 0 rgba(18,16,22,0.92), 0 5px 20px rgba(0,0,0,0.95), 0 0 32px rgba(0,0,0,0.88), 0 0 58px rgba(0,0,0,0.68), 0 0 96px rgba(0,0,0,0.42)",
  "captionDimUpcoming": false,
  "captionInstantIn": true,
  "captionMaxHoldMs": 240
}
```

Значения не подобраны на глаз — это замеры по кадрам образца:

| что | замер |
|---|---|
| центр строки | 0.679 высоты кадра (пять кадров: 0.678–0.683) |
| капитель | 76–88 px при 1920, медиана 82 |
| тень | жёсткое смещение 6px вниз-вправо, без размытия |
| ореол | спадает до нуля примерно к 50px от букв |
| ширина знака | 0.573 капители — у́же любой свободной гарнитуры |

Последнее — причина `captionScaleX`. Гарнитура образца узкая настолько, что
ближайший свободный аналог по рисунку и насыщенности (Oswald Bold, 0.727)
приходится сжимать до 0.788. Проверялись также Alumni Sans (0.699),
PT Sans Narrow (0.746), Fira Sans Extra Condensed (0.777) и Yanone Kaffeesatz
(0.565 — единственный, кто попал в ширину, но заметно легче по насыщенности).

`captionTextShadow` совмещает две вещи: жёсткую тень образца (первый слой, без
размытия) и **тёмное свечение вокруг букв** (три слоя размытия без смещения).
Свечение обязательно: без него белый текст на светлом кадре — например, на
белой футболке — разваливается и не читается. Три слоя нужны, чтобы ореол
спадал плавно: узкий и плотный у самых букв, широкий и слабый по краю. Одним
слоём получается либо ободок, либо грязное пятно.

`captionMaxHoldMs` снимает слово почти сразу после реплики. Без него последнее
слово фразы висит всю паузу и переживает склейку — на новом плане висит текст
от предыдущего.

Ореол активного слова цветом подсветки добавляется только когда
`highlightColor` отличается от `captionColor`. Если караоке-подсветка не нужна
и оба цвета совпадают, ореол не рисуется — иначе он спорил бы с тёмным
свечением.

`captionInstantIn` обязателен для такого стиля: пружинная анимация появления
занимает около 15 кадров, а слово держится на экране 8–10, поэтому без неё
слово не успевает проявиться и выглядит полупрозрачным.

### Осторожно с осью при замере цвета

Метрика насыщенности `(a.max(2) - a.min(2)).mean()` на массиве кадров
формы `(кадры, высота, ширина, канал)` берёт максимум **по ширине кадра**,
а не по каналам. Считается молча и даёт правдоподобные числа — поэтому
ошибка прожила несколько итераций подгонки и породила ложный вывод, будто
цветокор вдвое перенасыщен против образца.

Правильно — `axis=-1`. После починки оказалось, что цветность уже совпадала
с образцом (41.4 против 41.0), а отставала резкость (5.89 против 8.37).

Проверка, которая ловит такое за секунду: прогнать фильтр в двух крайних
положениях (`eq=saturation=0.3` и `1.4`) и посмотреть, двигается ли метрика.
Если пятикратное изменение параметра даёт 3% разницы — сломана метрика,
а не фильтр.

### Цветокор: мерить разделение, а не перцентили

Перцентили яркости — плохая цель для подгонки под образец, потому что они
описывают не обработку, а постановку света. В разборе образец давал
p75 = 126 при p75 = 75 у исходника, и никакая кривая эту разницу не
закрывала: у образца ярко освещённый объект на тёмном фоне, у исходника —
ровно залитая светлая стена. Попытка дожать p75 поднимает и стену.

Полезнее оказался замер по блокам кадра. У образца фон 16-51 при коже 123,
у исходника фон 29-98 при коже 96: объект ярче фона в 6.5 раза против 2.
Это и есть то, что глаз читает как «дорого». Отношение медиан
кожа/фон — цель, которую кривая действительно может двигать.

Форма — S-кривая с перегибом между стеной и лицом (около L = 75): ниже
уходит вниз, выше идёт вверх. Плюс отдельные кривые по каналам, иначе
теряется цветовой характер: у образца средние тона уведены в пурпур
(R-G +22.7, B-G +24.4), и нейтральная по цвету подгонка выглядит мёртвой,
как бы точно ни сходились яркости.

Виньетка поднимает совпадение: при angle=PI/11 разрыв объект/фон 6.43
против эталонных 6.47, тогда как без неё 5.73. Но она же выдаёт обработку —
затемнённые углы видны как приём, и владелец канала попросил её убрать.
Случай, когда лучшая по замеру настройка проигрывает по вкусу: цифра
описывает разделение планов, а не то, заметен ли способ, которым оно
получено.

Итог без виньетки: разрыв 5.73 против 6.47, средние тона 18.6/21.7 против
22.7/24.4, клиппинга нет.

### Цветокор: чего не надо делать

Первый прогон подгонялся под цифры образца и получил ошибку 0.107 — и
выглядел плохо. На стоп-кадре 1:1 было видно почему: лоб выбит в белое,
текстура кожи стёрта, брови ушли в рыжий, у оправы очков ореол от резкости.
Тени были придавлены в ноль (p5 = 0.9), насыщенность 0.978 — выше, чем у
самого образца (0.953).

Дешёвая картинка получается именно так: из клиппинга в светах и нулевых
теней. Дорогая — наоборот, держит детали на обоих концах. Рабочая связка
оказалась заметно скромнее по цифрам (ошибка ~0.25), но лучше на глаз:

```
hqdn3d=1.2:1.0:5:5,
curves=all='0/0 0.06/0.044 0.15/0.130 0.27/0.305 0.45/0.54 0.70/0.795 1/1',
eq=saturation=0.96:gamma=1.02,
unsharp=5:5:0.66:5:5:0.0
```

Тени садятся до p5 ≈ 5, а не до нуля; насыщенность уходит ниже единицы;
лёгкий шумодав перед резкостью убирает шум апскейла, не съедая текстуру.
Мораль: совпадение перцентилей — ориентир, а не цель. Разницу в постановке
света кривой не отыграть, и попытка дожать цифры ломает картинку.

### Титр верстается вслепую

Строка титра длиннее кадра молча уезжает за правый край: ffmpeg и Remotion
про это не сообщают, и обрезанное слово видно только на готовом рендере.
На втором ролике так потерялась половина слова «ГОЛОДАЮ» — и первая строка
тоже была за границей, на один пиксель.

Ширину можно посчитать заранее по таблицам шрифта, без рендера:

```python
advance = sum(hmtx[cmap[ord(c)]][0] for c in text)
width = advance / upm * font_size + (len(text) - 1) * letter_spacing_em * font_size
```

Дальше кегль уменьшается, пока строка не влезет в кадр минус отступы.
Дёшево и снимает целый класс ошибок, которые иначе ловятся глазами на
готовом файле.

### Шрифт заголовков

`OM Title` — авторская гарнитура канала (Rimma Sans Bold), лежит в
`fonts/RimmaSans-Bold.woff2`. Сабсет собран из исходного TTF и покрывает
кириллицу целиком (64/64 буквы плюс Ё/ё), латиницу, цифры и типографскую
пунктуацию. `HookTitle` использует её по умолчанию.

У `HookTitle` есть `dropShadow`: одна обводка читается как наклейка на
пёстром кадре, мягкая тень под ней сажает титр на картинку. Ещё есть
`inset` (левый вынос), `fontWeight` и `letterSpacing` по строкам.

Пока титр на экране, субтитры лучше гасить — два текста разом спорят друг с
другом, а титр и так проговаривается голосом. В конвейере это фильтр по
словам: всё, что начинается раньше `out_seconds` титра, не попадает в
субтитры.

Титр-крючок задаётся отдельным параметром `hookTitle`:

```json
{
  "hookTitle": {
    "in_seconds": 0.15, "out_seconds": 4.4, "top": 0.055, "strokeWidth": 6,
    "lines": [
      {"text": "ПОСЛЕ 6", "delay": 0.0,  "fontSize": 86},
      {"text": "ЕСТЬ",    "delay": 0.55, "fontSize": 100},
      {"text": "НЕЛЬЗЯ",  "delay": 1.1,  "fontSize": 100, "color": "#FD3233"}
    ]
  }
}
```

### Хвост ролика: проверять до рендера, а не после

Дважды подряд последнее слово оказывалось срезано затуханием: речь в
исходнике кончается позже, чем кажется по словам Whisper, — он растягивает
последнее слово на паузу. Проверка занимает секунду и делается по голосу,
а не по общей громкости (низкочастотный удар на финале маскирует тишину):

```
ffmpeg -ss <хвост> -i out.mp4 -af highpass=f=350 -f s16le -ac 1 -ar 16000 -
```

Затем смотрим, где падает энергия, и сравниваем с моментом начала
затухания. Запас меньше 0.3с — резать нельзя.

### Исправление распознанных слов

`--corrections corrections.json` принимает словарь замен — полезно для имён,
брендов и терминов, которые Whisper слышит неверно:

```json
{"клод": "Claude", "опенмонтаж": "OpenMontage"}
```

## Проверено

Прогон на 14-секундном вертикальном ролике 1080×1920: распознавание 48 с,
рендер 88 с, весь конвейер 2 мин 53 с, QA чистый. Тесты самого OpenMontage —
1827 passed, 1 failed (`test_network_guard`, проверяет отсутствие сети
в песочнице; к правкам отношения не имеет).

Ориентир для 50 секунд — 7–9 минут на 4 ядрах.

## Чего в бесплатном контуре нет

- **Фоновая музыка.** `pixabay_music` отдаёт 403. В репозитории есть только
  SFX (`whoosh`, `impact`, `riser`, `chime` — 19 файлов в
  `.agents/skills/hyperframes-media/assets/sfx/`). Для музыки нужен свой трек
  или бесплатный ключ Pixabay/Freesound.
- **Генерация видео и премиум-озвучка** — всё через платные API.

## Монтаж по образцу

Три скрипта в `reels/` закрывают то, ради чего обычно открывают монтажку:
разобрать сырьё, попасть в цвет образца и проверить, что попал.

```bash
python reels/take_split.py source.mov -o takes.json
python reels/grade_match.py --reference ref.mov --source source.mov \
    --chain "контраст=curves=all='0/0 0.1/0.07 0.27/0.44 0.59/0.79 1/1',eq=saturation=1.12"
python reels/caption_spec.py measure ref.mov
python reels/caption_spec.py check out.mp4 --position 0.679 --cap 95
```

### Что показал прогон на реальном материале

`take_split.py` появился не от хорошей жизни. Запись на 172 секунды — это
спикер, переснимающий каждую реплику по три-четыре раза. Whisper на таком
материале зацикливается: одна и та же фраза возвращается по десять раз
подряд, а тайминги слов растягиваются на всю паузу. Дубль как отдельный
запрос снимает и то, и другое, а список блоков сам оказывается списком
дублей.

Проверять сборку нужно расшифровкой самой сборки, а не доверием к плану.
Два раза из трёх границы, выбранные по словам Whisper, оказывались не там:
в один кусок попали три повтора одной фразы, в другой — фальстарт. Слышно
это стало только после того, как склеенная дорожка была распознана заново.

`grade_match.py` считает среднюю относительную ошибку по перцентилям
яркости. На связке «плоский исходник → образец с провалёнными тенями»
ошибка упала с 0.417 до 0.107. Дальше цифры не улучшались: разницу в
постановке света глобальная кривая не переносит, а попытка дожать
превращается в постеризацию. Виньетка, вопреки ожиданию, ухудшила замер
(0.268) — тёмный фон у образца не от виньетки, а от того, что фон не освещён.

`caption_spec.py` ищет текст по подписи жёсткой тени, а не по яркости:
белая футболка в кадре ярче субтитра. Ложные срабатывания остаются на
светлых деталях одежды, поэтому смотреть надо на медиану, а не на отдельный

Урок общий: прежде чем объяснять неожиданный разброс в данных, стоит

первой попытки измерить заведомо известный кадр.
